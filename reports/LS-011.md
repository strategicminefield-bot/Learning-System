### Authorization Check

**READ FROM A RECORD (migration_utility.py):** The endpoint performs **NO authorization checks**. It accepts any POST request with a `sql_content` body and executes it directly against the database. There is no authentication, API key check, or identity verification.

The only check is a generic `try/except` — errors are caught and returned as `{"success": false, "error": str(e)}`.

**INFERRED:** This is an unprotected, bare SQL execution endpoint. Any caller who can reach the API can execute arbitrary SQL.

The `apply/{n}` endpoint also returns the same error. This means the migration endpoint has likely **never been successfully called** — it cannot connect to the database because the Docker container's `DATABASE_URL` (`postgresql://fabric:fabric@postgres:5432/learning_fabric`) fails TCP password authentication while `docker exec` (Unix socket, no password) works.
